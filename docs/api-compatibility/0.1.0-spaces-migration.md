# Migrating from Petrel 0.1.0 to the Spaces candidate

The Spaces candidate combines the public module split, generated schema updates, and authentication and parser hardening that followed Petrel 0.1.0. These changes preserve ordinary calls for the moved public types, but they are not a promise of binary compatibility or complete source compatibility. The hosted SwiftPM comparison found 99 additional exact diagnostics that were absent from the older release allowlist. Each is classified below; the complete diagnostic inventory and originating commits are recorded in [the review manifest](0.1.0-spaces-review.json).

The comparison baseline is tag `0.1.0`, commit `02de350792158ffc9f2ad9902ac61f101ea84bca`. The reviewed runtime source is `e115236537041a900ec971be05185a70cca73e8a`. Its [newest-stable hosted comparison](https://github.com/joshlacal/Petrel/actions/runs/40049515308/job/120738797956) ran under Xcode 26.6, build 17F113, and failed on these 99 diagnostics. This follow-up records the reviewed migration from that historical baseline with exact allowlist lines; it does not disable the gate or permit wildcard matches. The repository also has a published 1.x release train: this check is not a comparison against the latest 1.x release and does not grant semantic-versioning approval for a future release.

## Authentication and parser behavior

OAuth callbacks require the persisted issuer, PDS origin, key thumbprint, redirect URI, and token-endpoint bindings, as well as one-time state and its bounded age. Flows started before those fields were persisted must restart. Keep the validation in place; filling nil fields to make an old initializer compile does not make old callback state acceptable. With `requireIssInCallback` enabled, `PublicOAuthStrategy` and `CABOAuthStrategy` (client assertion backend) require `iss`; the condition is not limited to whether metadata advertises it. Native public clients use the supported no-client-authentication configuration.

When handling `gatewaySessionRejected`, consume its proof through `withCurrentGatewaySessionFailure` around the synchronous UI transition, retaining the application's own client/session continuity checks. Checking the proof, suspending, and then logging out can act on a replacement session. Any later cleanup must be local-only or explicitly bound to the rejected credential.

The baseline comparator skips PetrelCore because that module did not exist in 0.1.0. Consequently, its relocation diagnostics do not list every new case on moved enums. Exhaustive switches must also handle `DAGCBORError.depthLimitExceeded`, `nodeLimitExceeded`, `unconsumedTrailingBytes`, and `invalidLength`, plus `CARReaderError.blockCIDMismatch` and `duplicateBlockConflict`. These cases retain bounded parsing, complete-consumption checks, and verified CAR block identity. Do not suppress them or turn rejected input into a successful parse.

## Evidence and limits

[The consumer probe](0.1.0-consumer.swift) compiles real calls using only `import Foundation` and `import Petrel`, including qualified moved names, old equality overloads, ordinary constructor calls, and CID-bearing generated initializers. Local Apple Swift 6.4/macOS 27 compiled it to an arm64 object with warnings as errors against the unchanged runtime modules. This is source/object compilation evidence, not linking, binary compatibility, execution, old-toolchain compatibility, or production acceptance.

The companion [exact-initializer probe](0.1.0-old-init-references.swift), [nonoptional-CID probe](0.1.0-repoop-nonoptional.swift), and [old enum-switch probe](0.1.0-old-enum-switches.swift) intentionally fail compilation, exposing the migration obligations above. They are evidence fixtures, not examples that should compile successfully. The initial ASN.1 probe could not import SwiftASN1 from the Petrel build products. A separate consumer package explicitly declaring the SwiftASN1 product from clean source revision `f70225981241859eb4aa1a18a75531d26637c8cc` then compiled all 13 `Int`/`Bool` conformance assertions with warnings as errors. Both outcomes are retained: incidental exposure is absent, and the explicit-dependency migration compiles.

The hosted API gate remains required for the follow-up commit; the prior failed comparison and these local probes do not establish a passing hosted result. The separate runtime integration graph intentionally remains at Petrel `e115236537041a900ec971be05185a70cca73e8a` and PetrelCatbird `8672c80ffeb3b9cfbdb6bd98f66efa09b13fe0db`. The follow-up changes only review metadata, documentation, and these documentation fixtures. No package source, dependency manifest, lockfile, generator, workflow, or runtime policy changes are included.
